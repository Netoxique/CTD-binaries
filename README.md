# CTD-binaries

Built CTD release packages and installation entry points. The CTD source
repository is the source of truth for both installers: copy `install_online.sh`
and `install_offline.sh` here whenever they change, and keep Unix (LF) line endings.

## Installation

Run installers on the Raspberry Pi as root. Both installers reboot the unit
after a successful installation.

- **Online (Trixie):** run `sudo bash install_online.sh`. It downloads
  `Magno-<OS codename>.tar.gz` from this repository's latest GitHub release.
  Buster runs offline and is rejected before downloading.
- **Offline (Buster or Trixie):** place the matching release archive at
  `/home/pi/Desktop/CTD/Magno-<OS codename>.tar.gz`, then run
  `sudo bash install_offline.sh`. For example, use `Magno-trixie.tar.gz` on Trixie
  or `Magno-buster.tar.gz` on Buster. The archive location is fixed; it is not
  resolved relative to the script.

The archive must contain `LCD.dist/`, including `LCD.bin`, `VERSION`, `lib/`,
`Install/`, `Services/`, and the other resources assembled by CTD's `build.sh`
or `bundle_dist.sh`. Use a current package with these installers.

The installers preserve existing `/home/pi/Desktop/CTD/lib/test_files`,
`lib/config.ini`, and `event_reporting.json` when present. Missing runtime
configuration is generated by CTD on startup. They copy `VERSION` to the runtime
directory and run every bundled `Install/*.sh` script in filename order.
Service setup belongs to those bundled scripts, including the Buster policy
of installing only `ctd.service`. Exit code `10` from `service_check.sh` is
accepted as success; other script failures stop installation before reboot.
The completion marker is written only after a successful install-script pass.

## Client updates

Existing clients use `update_online.sh` or `update_offline.sh` from their installed
release package. Those scripts are maintained and packaged by the CTD source
repository; copying these installers alone does not update existing clients.

## Maintenance notes

These installers retain CTD's current installation behavior: they replace
`/home/pi/Desktop/CTD`, reset `/etc/rc.local`, and delete the contents of
`/home/pi/Documents/`. Back up any unrelated files in those locations before
installation. Package extraction overlays `/opt/ctd/LCD.dist`; installation
does not provide transactional rollback or stop an already running CTD service.
Use the packaged update flow for routine client updates.
